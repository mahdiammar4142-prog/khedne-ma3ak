# How Khedne Ma3ak Works – Step by Step

A detailed walkthrough of the application flow from startup to each feature.

---

## 1. App Startup

1. **`main.dart`** runs:
   - Ensures Flutter bindings are initialized
   - Sets up error handling (prints exceptions to debug console)
   - **Initializes Firebase** with `Firebase.initializeApp()` using `firebase_options.dart` (generated by `flutterfire configure`)
   - Wraps the app in `ProviderScope` (Riverpod) for state management
   - Builds `LebanonPlacesApp` with `MaterialApp.router`, theme, and `appRouter`

2. **Router** (`app_router.dart`):
   - Starts at `/gate` (initial location)
   - Before every navigation, runs `_redirect()` to decide where the user should go

---

## 2. Auth Gate & Redirect Logic

**Redirect rules** (in `_redirect`):

| User state | Current route | Redirect to |
|------------|---------------|-------------|
| Logged in (Firebase user) | `/gate` | `/home` |
| Guest (Continue as guest) | `/gate` | `/home` |
| Not logged in, not guest | Any protected route | `/gate` |
| On `/gate`, `/login`, `/register` | — | Stay (no redirect) |

**Gate screen** (`gate_screen.dart`):
- Shows logo, "Khedne Ma3ak", and tagline
- Three options:
  - **Log in** → navigates to `/login`
  - **Create account** → navigates to `/register`
  - **Continue as guest** → calls `AuthRepository.setGuest(true)` (saves to SharedPreferences), then `context.go('/home')`

---

## 3. Login Flow

1. User taps **Log in** on gate → goes to `LoginScreen`
2. User enters email and password
3. On submit: `AuthRepository.signInWithEmailAndPassword()` → Firebase Auth
4. On success: `context.go('/home')`
5. Guest flag is cleared (`clearGuest()`) so the user is treated as logged in

---

## 4. Registration Flow

1. User taps **Create account** on gate → goes to `RegisterScreen`
2. User enters name, email, password
3. On submit:
   - `AuthRepository.createUserWithEmailAndPassword()` → Firebase Auth creates the user
   - `user.updateDisplayName(name)` → sets display name in Firebase
   - `UserProfileRepository.createProfile()` → creates a document in Firestore `users/{uid}` with displayName, email, photoUrl, timestamps
4. On success: `context.go('/home')`

---

## 5. Home Screen

**Layout:**
- **Header:** "Khedne Ma3ak" title, search icon → `/search`, chatbot icon (sparkle) → `/chatbot`, star icon (placeholder)
- **Top nav:** Activity, Bookings, Profile → `/profile`
- **2×2 category grid:**
  - Pools And Beaches → `/search` with query `"pool"`
  - Restaurants → `/search` with query `"restaurant"`
  - Sports & Activities → `/search` with query `"activity"`
  - Hotels and Guesthouses → `/search` with query `"hotel"`
- **Bottom nav:** Taxi (placeholder), Explore → `/map`, Add Location (placeholder)

---

## 6. Search Flow (Smart Taxonomy)

1. User reaches **PlacesSearchScreen** (from home category tap, or search icon)
2. Search bar: user types e.g. `"burgers"` or `"pool"`
3. **Taxonomy** (`taxonomy_model.dart`):
   - `Taxonomy.categoriesForQuery(query)` maps keywords to `PlaceCategory`:
     - `"burgers"` → `[restaurant, snacks]`
     - `"pool"` → `[pool]`
     - `"hotel"` → `[hotel]`
   - Uses synonyms (e.g. "shisha" → nightlife, "resort" → hotel + pool)
4. **PlacesRepository** (currently `DemoPlacesRepository`):
   - `search(query, categories)` filters the in-memory list of 26 demo places
   - Matches: (1) category from taxonomy, (2) name/description/tags containing the query
5. Results shown in a `ListView` of `PlaceCard` widgets
6. User can tap **Show on map** → `/map` with the same query
7. User taps a place card → `/search/place/:id` → `PlaceDetailScreen`

---

## 7. Place Detail

1. `PlaceDetailScreen` receives `placeId` from route
2. Uses `placeDetailProvider` (Riverpod) → `PlacesRepository.getById(id)`
3. Shows name, description, category, region, rating, address, map snippet
4. **Book / Plan trip** button → `url_launcher` for phone/website if available

---

## 8. Map Screen

1. `PlacesMapScreen` receives optional `initialQuery` from route
2. Uses `mapPlacesProvider(query)` → same `PlacesRepository.search()` as search
3. Renders Google Map centered on Lebanon (Beirut) with markers for each place
4. Tapping a marker shows info window; user can navigate to place detail

---

## 9. Chatbot Flow

1. User taps chatbot icon (sparkle) on home → `ChatbotScreen`
2. Initial message: greeting and hint ("Ask me for recommendations...")
3. User types a message and sends
4. **AiChatService** decides how to get a reply:

   **On Web:**
   - Calls Firebase Cloud Function `chatWithGemini` via `FirebaseFunctions.instance.httpsCallable()`
   - Function receives `message` and `sessionId`, calls Gemini API, returns `{ reply: text }`
   - Avoids CORS (browser blocks direct Gemini calls)

   **On Mobile/Desktop (Android, iOS, Windows):**
   - Calls Gemini API directly via `google_generative_ai` package
   - Uses API key from `gemini_config.dart`

5. If AI fails or is unavailable → **fallback** keyword replies:
   - "guide" → suggests opening the Guide
   - "burger"/"restaurant"/"food" → suggests search + Roadster Diner
   - "pool"/"beach" → suggests Le Bristol, Mövenpick
   - "hotel"/"stay" → suggests hotel search
   - "trip"/"plan" → suggests Trip planning
   - Default → generic help message

6. Reply is appended to the message list and displayed

---

## 10. Guide Screen

1. User navigates to `/guide` (e.g. from a link or future nav)
2. Uses `guidePlacesProvider` which depends on `guideCategoryProvider`
3. Can filter places by category; if no category selected, shows all
4. Same `PlacesRepository.search('', categories: [cat])` under the hood

---

## 11. Events Flow

1. **Create event:** `CreateEventScreen` → user enters name, date, description, adds members
2. `EventsRepository.create(event)` → in demo, adds to in-memory list
3. **Event detail:** `EventDetailScreen` shows event, suggested places, voting
4. Members vote with `EventsRepository.addVote(eventId, placeId, userId)`
5. Organizer can `setSelectedPlace()` to finalize the venue

*Note: Events use `DemoEventsRepository` (in-memory). Firestore version can be wired similarly to places.*

---

## 12. Profile Screen

1. Shows user info (from Firebase Auth + Firestore profile if logged in)
2. Guest users see limited or different UI
3. **Sign out** → `AuthRepository.signOut()` → clears guest flag, Firebase sign out → redirect sends user back to `/gate`

---

## 13. Trip Planning

1. `TripPlanningScreen` is a placeholder
2. Intended for trip planning and booking links
3. Place detail already has "Book / Plan trip" with `url_launcher` for phone/website

---

## Data Flow Summary

```
┌─────────────────────────────────────────────────────────────────┐
│                         Flutter App                              │
├─────────────────────────────────────────────────────────────────┤
│  UI (Screens)  →  Riverpod Providers  →  Repositories            │
│       ↓                    ↓                      ↓              │
│  gate_screen      authRepository        AuthRepository            │
│  home_screen      placesRepositoryProvider  → DemoPlacesRepository │
│  search_screen    searchResultsProvider     (or FirestorePlaces)   │
│  chatbot_screen   (none - direct)          AiChatService           │
│  ...                                                              │
└─────────────────────────────────────────────────────────────────┘
         │                    │                      │
         ▼                    ▼                      ▼
   go_router           SharedPreferences      Firebase (Auth, Firestore)
   (navigation)        (guest flag)            Cloud Functions (web)
```
